# Change-watcher prompt — v1

Role: `REASONER` (`gpt-5.1` primary, `gpt-5.6-luna` fallback). Used by
`src/agents/change_watcher_agent.py`, only for regions the
deterministic diff already classified as a genuine textual change (never
for pure whitespace/case reflows) that overlap an existing tracked
obligation's cited source text.

## Instructions

1. Compare `old_clause_text` (what the obligation was originally extracted
   from) against `new_clause_text` (the same location in the updated
   regulation). Decide whether the change is substantive or editorial.
2. `materiality` must be exactly one of: `high`, `medium`, `low`, `editorial`.
   - `high`: the obligation's actor, modality (must/should/may), deadline, or
     scope changed in a way a previously-compliant control might no longer
     satisfy.
   - `medium`: a real requirement changed but likely still within the
     existing control's design intent.
   - `low`: minor wording change, requirement substance unchanged.
   - `editorial`: no substantive change at all (should be rare here — the
     deterministic diff already filtered pure whitespace/case reflows).
3. `breaks_control`: `true` only if the control described below, as
   designed, would plausibly no longer satisfy the obligation under the new
   wording (e.g. a tightened deadline the control's frequency can't meet, a
   widened scope the control doesn't cover). Do not set `true` merely
   because the wording changed — judge against the control's actual design.
4. `obligation_delta`: one sentence naming exactly what changed about the
   obligation itself (e.g. "reporting deadline tightened from 24h to 12h
   after detection"), not a restatement of the whole clause.
5. `rationale` must reference both `old_clause_text`/`new_clause_text` and
   the control's design — a materiality or `breaks_control` verdict with no
   textual grounding is not acceptable.

## Input

```
old_clause_text: {{old_clause_text}}
new_clause_text: {{new_clause_text}}

obligation_text: {{obligation_text}}
obligation_modality: {{obligation_modality}}
obligation_deadline: {{obligation_deadline}}

control_title: {{control_title}}
control_design_description: {{control_design_description}}
control_automation: {{control_automation}}
control_frequency: {{control_frequency}}

existing_coverage_level: {{existing_coverage_level}}
```

## Output schema

Respond with **only** a JSON object, no prose before or after it:

```json
{
  "materiality": "high",
  "breaks_control": true,
  "obligation_delta": "one sentence describing exactly what changed",
  "rationale": "grounded in both clause texts and the control's design"
}
```
